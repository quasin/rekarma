# ReKarma — agent notes

Distributed recommendation system. Zig 0.17.0 executable that links the
prebuilt librats (C++ p2p/DHT/bittorrent) release; Autonomi `ant-client` is
installed by `install.sh` for later use. Today `main.zig` only prints a banner
and reads the librats version out of the linked library.

## Layout

    src/main.zig                  executable entry point (root of the `rekarma` exe)
    src/c.h                       every C #include the project needs, in one header
    build.zig                     librats guard, translate-c module, runtime linking
    build.zig.zon                 package manifest (min zig 0.17.0; .paths = tracked paths only)
    scripts/fetch-librats.sh      downloads+lifts the prebuilt librats release into vendor/
    scripts/librats/features.h    hand-written shim for a header the release omits (tracked)
    vendor/librats/               GENERATED by the fetch script — gitignored, never committed
    install.sh                    ant-client installer + fetch-librats.sh
    main.sh                       standalone banner echo (not part of the build)

## Commands

    zig build                                 # link the exe -> zig-out/bin/rekarma
    zig build run                             # build + run
    zig build run -- <args>                   # pass args (run_cmd.addPassthruArgs)
    zig build -Dlibstdcpp=/path -Dlibgcc_s=/path   # override system C++ runtime paths
    bash install.sh                           # ant-client + fetch librats (first setup)
    bash scripts/fetch-librats.sh             # (re)fetch librats after a clone or to bump

There is no test step wired in `build.zig` yet.

## Hard constraints

- **Zig 0.17.0** (`build.zig.zon` `.minimum_zig_version`). No inline `@cImport` —
  C headers are translated into a module by `b.addTranslateC` in `build.zig` from
  `src/c.h`, then imported as `@import("c")`. Add new C includes to `src/c.h`, not
  to Zig files.
- **`librats.a` is GCC-built C++ (`__cxx11` ABI).** It must link the *system*
  libstdc++ and `/usr/lib/libgcc_s.so.1`, not Zig's bundled libc++ (which has no
  `__cxx11`). That is why `build.zig` uses `addObjectFile` for both rather than
  `linkSystemLibrary("stdc++")`. Paths are `-Dlibstdcpp=` / `-Dlibgcc_s=` options.
- **`vendor/librats/` is generated, gitignored, and replaced wholesale by the
  fetch script.** Anything hand-written must live outside it, in `scripts/librats/`
  (see `features.h`, copied in by the script). Do not commit anything under
  `vendor/`; do not try to `!`-negate a file inside it (a negation cannot re-include
  into an ignored directory).
- **`build.zig` fails loudly when librats is missing** (`std.Io.Dir.cwd().access`
  on `vendor/librats/librats.a`) instead of a raw linker error. That check resolves
  against the cwd `zig build` was run from (the project root).

## Conventions

- Comments explain *why*, not *what* — every non-obvious choice (translate-c, the
  libstdc++/libgcc_s wiring, the vendoring rule, the features.h shim) carries a
  comment naming the reason. Match that density.
- `.gitattributes` enforces `text=auto eol=lf`; keep files LF.
- `build.zig.zon` `.paths` lists only tracked paths — a generated dir (e.g.
  `vendor`) absent on a fresh clone must not be listed.
- Plain `bash` scripts with `set -euo pipefail`; comment the purpose in a header block.

## Validate a change

    zig build            # must exit 0
    zig build run        # prints the banner + the linked librats version/abi
